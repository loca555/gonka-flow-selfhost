# Проверки комплекта для самостоятельного размещения Flow

Подготовлено 28 октября 2026 года. Текущий сервер и конфигурация проекта не менялись.

Локально выполнено:

- `docker compose config` с `.env.example` — успешно, без запуска контейнеров.
- Разбор трёх Python-скриптов — успешно.
- Сборка публичного интерфейса из доступных статических исходников Flow под `https://flow.example.com` — 16 файлов.
- SHA256 всех файлов, перечисленных манифестом сборки, совпали.
- В полученных файлах нет ссылок на Render и не осталось строковых API-путей, которые сборщик должен был переписать.
- В Compose наружу не опубликованы 5001, 8000, 8080 и 2019.
- Архив комплектуется по явному списку файлов: локальная пробная сборка, данные, настоящая `.env` и резервные копии в него не входят.

На целевом Linux-сервере ещё нужно выполнить проверки из README: скачивание конкретных образов, синтаксическую проверку Caddy его бинарным файлом, работу DNSLink через Kubo, TLS, API/индексатор и резервное копирование с пробным восстановлением. Локальная пробная сборка использовала доступные исходники; инструкция для хостера извлекает статику из его конкретного Docker-образа.

При первоначальной проверке комплекта контейнеры или серверы не запускались. DNS, ENS и действующий Flow не менялись. Публикация самого гайда в GitHub не является запуском описанного размещения.

Дополнительная проверка 28 октября: исправлено имя рабочей базы в `backup_db.py` и `restore_db.py` — `gonka-flow.sqlite3`. Имя архива публичного снимка `wgnk.sqlite3.gz` от этого не меняется. В отдельном одноразовом Linux-контейнере без сети и рабочих данных проверены восстановление синтетической SQLite-базы, `integrity_check`, отказ при существующей базе или WAL и резервное копирование от UID 10001 с правами 0600. Эта проверка не подтверждает работу TLS, DNSLink или всего размещения на чужом сервере.
